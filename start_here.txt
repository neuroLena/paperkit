# PaperKit — Installation and startup

## 1. Configure Git identity (first time only)

Check that Git is installed:

```bash
git --version
```

Configure your name and GitHub email:

```bash
git config --global user.name "YOUR_NAME"
git config --global user.email "YOUR_GITHUB_EMAIL"
git config --global github.user "YOUR_GITHUB_USERNAME"
```

Verify the configuration:

```bash
git config --global --get user.name
git config --global --get user.email
git config --global --get github.user
```

These settings identify the author of Git commits but do not authenticate your GitHub account.

## 2. Configure GitHub SSH authentication (first time only)

Create the SSH configuration directory:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
```

Check whether an SSH key already exists:

```bash
ls -la ~/.ssh
```

If `id_ed25519` and `id_ed25519.pub` do not exist, generate a new key:

```bash
ssh-keygen -t ed25519 -C "$(git config --global user.email)"
```

Press Enter to accept the default location. Optionally, enter a passphrase to protect the key.

Start the SSH agent:

```bash
eval "$(ssh-agent -s)"
```

Add your SSH key:

```bash
ssh-add --apple-use-keychain ~/.ssh/id_ed25519
```

Create or open the SSH configuration file:

```bash
touch ~/.ssh/config
chmod 600 ~/.ssh/config
nano ~/.ssh/config
```

Add the following configuration if a GitHub entry does not already exist:

```text
Host github.com
    HostName github.com
    User git
    AddKeysToAgent yes
    UseKeychain yes
    IdentityFile ~/.ssh/id_ed25519
```

Copy your public SSH key:

```bash
pbcopy < ~/.ssh/id_ed25519.pub
```

Open https://github.com/settings/keys in your browser.

Select **New SSH key**, enter a descriptive title, paste the public key and save it.

Test authentication:

```bash
ssh -T git@github.com
```

On the first connection, verify the server fingerprint against GitHub's published SSH fingerprints before accepting it.

Expected response:

```text
Hi YOUR_USERNAME! You've successfully authenticated,
but GitHub does not provide shell access.
```

## 3. Set up PaperKit

Navigate to the repository root:

```bash
cd paperkit
```

Run the setup script:

```bash
bash setup.sh
```

For an existing project, run:

```bash
UPDATE_CODE=1 bash setup.sh
```

Your `paper.yaml` is never overwritten, so add the Introduction section manually if it is missing.

## 4. Generate a GitHub Personal Access Token

Open:

https://github.com/settings/tokens

Select **Tokens (classic) → Generate new token (classic)**.

Configure:

- Note: PaperKit publishing
- Expiration: 30 or 90 days
- Scope: repo

Generate the token and copy it securely.

The token is required for automatically creating a new GitHub repository through the REST API. Subsequent Git pushes use SSH authentication.

## 5. Configure environment variables

The centralized `.env` file should be located in the root `paperkit/` directory.

If the setup script has not already created it:

```bash
touch .env
chmod 600 .env
```

Open the file:

```bash
nano .env
```

Configure the required credentials:

```dotenv
# GitHub configuration
GITHUB_USER=YOUR_GITHUB_USERNAME
GITHUB_TOKEN=YOUR_GITHUB_TOKEN
VISIBILITY=private

# NVIDIA API configuration
NVIDIA_API_KEY=YOUR_NVIDIA_API_KEY

# Anthropic API configuration (optional)
ANTHROPIC_API_KEY=
```

Save with Ctrl+C, Enter, and exit with Ctrl+X.

Ensure that credentials are excluded from Git:

```bash
touch .gitignore

grep -Fxq '.env' .gitignore || \
    printf '\n.env\n' >> .gitignore

chmod 600 .env
```

If the Git repository has already been initialized, verify the exclusion:

```bash
git check-ignore -v .env
```

Load the environment variables into the current terminal session:

```bash
set -a
source .env
set +a
```

## 6. Activate the Python environment

```bash
source .venv/bin/activate
```

Verify the installation:

```bash
python --version
which python
paperkit --help
```

Run automated tests:

```bash
python -m pytest -v
```

source .venv/bin/activate
cd sci_paper_writing_agent
paperkit extract facts
paperkit extract key-messages


## 7. Publish the repository to GitHub

From the root `paperkit/` directory:

```bash
bash publish.sh "Initial commit"
```

The publishing script will:

- Initialize the local Git repository if necessary.
- Check for nested Git repositories.
- Check Git exclusions.
- Scan staged files for recognizable API keys.
- Commit the project.
- Ask for a GitHub repository name if no remote is configured.
- Create a private or public repository using the GitHub API.
- Configure the SSH remote.
- Push the project to GitHub.

To specify the repository name directly:

```bash
REPO_NAME=my-paperkit VISIBILITY=private \
    bash publish.sh "Initial commit"
```

Verify the configured remote:

```bash
git remote -v
```

## 8. Start PaperKit

```bash
paperkit start
```

## 9. Subsequent sessions

The initial installation, SSH setup and GitHub token creation do not need to be repeated.

To start the application:

```bash
cd paperkit
source .venv/bin/activate
paperkit start
```

To update the application:

```bash
UPDATE_CODE=1 bash setup.sh
```

To test the application:

```bash
python -m pytest -v
```

To commit and publish changes:

```bash
bash publish.sh "Describe changes"
```

To commit locally without uploading to GitHub:

```bash
LOCAL_ONLY=1 bash publish.sh "Local changes"
```

To retrieve changes from GitHub:

```bash
git pull
```

## 10. Security

Never upload the following files or directories to GitHub:

- `.env` and other files containing credentials.
- Private SSH keys.
- `.venv/`.
- `.papers/`.
- `.writing_guides/`.
- `.cache/`.
- Confidential research data.
- Agent logs containing sensitive research information.

Only public SSH keys ending in `.pub` should be uploaded to GitHub's SSH key settings.
